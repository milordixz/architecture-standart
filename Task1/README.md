## Карта текущего IT-ландшафта

Столбцы буквально соответствуют шести возможностям второго уровня исходной BCM. Продажи и маркетинг: первые три; поддержка операционных процессов: последние три. Строки — подразделения, а не приложения. Партнёрский кол-центр показан отдельно как внешняя организация из текста условия; он не является подразделением банка.

## Реестр взаимодействий AS-IS

Идентификаторы I01…I14 нанесены на схему. Сплошные линии обозначают системный обмен/работу пользователя, красный пунктир — ручной процесс (Email, Excel, скрипты), синий пунктир — путь клиента. Указаны данные и направление; точные неизвестные протоколы не придуманы.

| ID | Откуда → куда | Данные / действие | Основание и ограничение |
| --- | --- | --- | --- |
| I01 | Клиент → сайт | Просмотр маркетинговых материалов | Факт; без заявки на депозит |
| I02 | Клиент → интернет-банк | Платежи, текущие счета | Факт; без депозитов |
| I03 | Интернет-банк → БД АБС | Данные/операции платежей и счетов | Прямая интеграция с БД — факт; конкретные SQL/процедуры не описаны |
| I04 | Клиент → фронт-офис → АБС | Личная заявка, открытие депозита, подписанные документы | Факт; пользователь АБС работает в Delphi |
| I05 | Клиент → оператор → система кол-центра | Звонок, регистрация обращения | Факт; канал голосовой связи не детализирован |
| I06 | Система кол-центра → АБС | Обращение клиента | Факт; транспорт не определён |
| I07 | Депозитный бэк-офис → АБС | Обработка обращений, фиксация ставки | Факт |
| I08 | Кредитный бэк-офис → АБС | Анализ кредитного риска | Факт; отдельная область доступа |
| I09 | Кредитный бэк-офис → Excel → почта → депозитный бэк-офис | Ежедневные ставки, данные для индивидуальной ставки | Факт; обмен не является API |
| I10 | Фронт-офис ↔ почта ↔ депозитный бэк-офис | Запрос и ответ со ставкой | Факт; ожидание клиента 20–60 минут |
| I11 | Депозитный бэк-офис ↔ почта ↔ кредитный бэк-офис | Запрос анализа риска, ответ для специальной ставки | Факт; разделение доступа к исходным данным |
| I12 | АБС → СМС-шлюз → телеком-оператор → клиент | Уведомление о доступной ставке и визите в отделение | Уведомление — факт; маршрутизация через единственный описанный шлюз — допущение A1 |
| I13 | Бизнес-представитель → партнёрский кол-центр | Готовые скрипты звонков | Факт; канал передачи не определён, автоматической синхронизации ставок нет в условии |
| I14 | Оператор партнёра → внешняя система; клиент ↔ оператор | Консультация по скрипту | Работа партнёра — факт; технические детали внешней системы неизвестны |

На схеме отдельным блоком показана собственная MS SQL интернет-банка. Система кол-центра: React.js, Java Spring Boot, PostgreSQL, микросервисы, размещение в банке. АБС: Delphi + Oracle/PL-SQL. Внешний кол-центр и подрядчик банковского кол-центра — разные организации.

## Препятствия цифровому продукту

1. Ставки живут в Excel и письмах: нет версионированного источника, доступного каналам.
2. Особая ставка требует ручного обмена между подразделениями с разными правами.
3. Депозит оформляет фронт-офис; клиент ждёт согласований и подписывает документы лично.
4. Интернет-банк напрямую связан с перегруженной Oracle АБС; рост онлайн-запросов переносит нагрузку в критичный контур.
5. Интернет-банк работает в одном ЦОД; резервный ЦОД ещё не обеспечивает целевой уровень доступности.
6. Кол-центры не получают единый актуальный каталог ставок. Сайт не принимает заявки.
